# AutoJs6 LSP declaration generation

The source declarations remain under:

`app/src/main/assets/editor/ace-builds-1.4.12/autojs6/types`

Generate the runtime bundles with:

```powershell
.\gradlew.bat :app:generateAutoJs6LspDeclarations
```

Android asset merging and APK assembly depend on this task automatically.
External scripts may call the task directly after updating declarations. If
Node is not available on `PATH`, pass
`-Pautojs6.nodeExecutable=<absolute-node-path>`.

The task:

- keeps every source declaration unchanged;
- validates triple-slash paths and TypeScript 6 syntax;
- emits deterministic `core`, `android`, `libraries`, `resources`, and
  `main-app` bundles plus `manifest.json`;
- removes recursive path directives, hoists required TypeScript `lib`
  directives, normalizes legacy identifier `module` declarations, and changes
  the known empty core `App` forward class into a mergeable interface only in
  generated output;
- writes only below `app/build/generated/aceLspAssets`.

The runtime always loads the generated `core` group together with
`lib.autojs6.extra.d.ts`. The latter is a deliberately small compatibility
root that only retains the legacy `AutoJs6.App.PackageName`, `AppName`, and
`Alias` type names without redeclaring current core symbols.

`aj6-int-*.d.ts` files are discovered as core declarations automatically.
Other new core files must be referenced from `autojs6/index.d.ts`; an
unclassified declaration fails generation instead of being silently ignored.

Optional group dependencies are:

- `libraries` → `android`
- `main-app` → `android`, `libraries`, `resources`

All optional groups are disabled by default in the host editor settings.

## M2 static-completion indices

Python, Lua, Java, and Kotlin use deterministic, project-maintained static
indices generated by `generate-language-indices.mjs`. The pinned factual API
baselines are Python 3.12 with typeshed commit
`d097b16922b98d06980c4be8050b44132da76ba1`, Lua 5.4.8, Java 17 with Android
API 35, and Kotlin 2.2.21. The generated data contains selected API names and
signatures plus project-authored descriptions; it does not copy upstream stub
files, source code, or documentation prose.

Regenerate the committed assets with:

```powershell
.\gradlew.bat :app:generateAutoJs6LanguageIndices
```

Check that committed assets exactly match the generator without writing them:

```powershell
.\gradlew.bat :app:verifyAutoJs6LanguageIndices
```

The lower-level CLI also supports `--out-dir <path>` and `--check`. The default
output is
`app/src/main/assets/editor/ace-builds-1.4.12/autojs6/indices/`. Language keys,
modules, members, aliases, and generated files are sorted before serialization,
so identical generator input produces a byte-identical result.

`:app:verifyAutoJs6LspRuntime` depends on the deterministic check and then
validates lazy loading, schema completeness, current-document symbol extraction,
language isolation, JavaScript regression behavior, the 50 ms load/parse budget,
and the 2 MiB per-language runtime estimate. See
`M2_COMPLETION_ACCEPTANCE.md` and `MILESTONE_BASELINES.md` for the acceptance
matrix and measured device results.

## M3 semantic-provider and LSP framework

The browser runtime now separates semantic capability, protocol, and transport:

- `autojs6_semantic_provider.js` defines the eight-capability provider contract,
  health/degradation state, the fixed semantic → M2 → document-word completion
  chain, and the `TypeScriptInProcessProvider` adapter;
- `autojs6_lsp_core.js` implements transport-independent JSON-RPC/LSP document
  synchronization, requests, cancellation, version filtering, diagnostics,
  snippet conversion, restart recovery, and root-confined atomic workspace edits;
- `autojs6_lsp_transports.js` supplies WebWorker/postMessage and Android bridge
  stdio transports with handshake, crash detection, bounded restart backoff, and
  idle exit;
- the Kotlin stdio bridge uses UTF-8 `Content-Length` framing and accepts only
  opaque provider IDs whose fixed `ProcessBuilder` specs are registered in the
  application. JavaScript cannot submit an executable command or environment.

TypeScript 6.0.3 runs through the new provider without changing its public
behavior. M3 originally left Python, Lua, Java, and Kotlin on M2 by default.
M4 enabled the bundled Python provider by default, and M5 now enables LuaLS on
its supported Android ABIs; Java and Kotlin remain on M2 until their
corresponding runtime milestones. The file-type preference revision is 3, and
migration changes only untouched historical defaults, never a custom list.

`:app:verifyAutoJs6LspRuntime` runs the provider failure/timeout suite, the full
protocol mock suite, and the same initialize/echo/shutdown suite over both
transports. Kotlin tests cover framing and process lifecycle. See
`M3_SEMANTIC_FRAMEWORK_ACCEPTANCE.md` for the protocol matrix, safety rules,
asset hashes, and Android 9–16 results.

## M4 Python semantic Worker

Python 3.12 semantics use a lazy WebWorker build of Pyright `1.1.413` at commit
`789d8275fef25f347ffef7b847305fefd8a3e363`. The bundle contains 271 files from
typeshed commit `289e5d3568961c8bcd33d01eef5b7ec5e1ad33ad`: builtins, the selected M2
standard-library roots, and their top-level import closure. It deliberately
contains no third-party stubs or project/venv resolver.

The provider supplies completion, hover, signature help, diagnostics, and
definition through the M3 JSON-RPC/LSP core and WebWorker transport. The
semantic asset set is 4.822 MiB, below the 8 MiB optional-delivery threshold,
so it is committed and works fully offline. `python/manifest.json` pins all
input versions and hashes; `python/THIRD_PARTY_LICENSES.txt` contains the 14
redistributed runtime components.

Regenerate from the pinned upstream source with either entry point:

```powershell
node tools/ace-lsp/build-python-worker.mjs

# Reuse an already checked-out Pyright tree.
node tools/ace-lsp/build-python-worker.mjs `
  --pyright-dir <path-to-pyright-1.1.413>

.\gradlew.bat :app:generateAutoJs6PythonWorker
# Gradle accepts -Pautojs6.pyrightDir=<path> for the same offline-source mode.
```

Normal asset merge and APK assembly do not regenerate or download this large
dependency graph. They package the committed asset. Verify its exact pins,
license inventory, size, semantics, failure fallback, and release lifecycle with:

```powershell
.\gradlew.bat :app:verifyAutoJs6PythonWorker
```

The Worker output currently requires ES2022 public class fields, optional
chaining, and nullish coalescing. `PythonProvider` probes those constructs
before creating a Worker. An older WebView, a missing asset, or an initialize
failure therefore falls silently through the normal M2 Python index, without a
five-second handshake stall or an error dialog. Android 10 / WebView 74 is an
explicit automated fallback fixture.

Measure the runtime's baseline-subtracted host + attributed WebView-renderer
PSS on connected devices with:

```powershell
.\tools\ace-lsp\measure-python-semantic.ps1 `
  -Serial BH900ASK9E,QV710AF65F -HoldMs 15000 -SkipBuild
```

See `M4_PYTHON_SEMANTIC_ACCEPTANCE.md` for the Pyright versus Pyodide/Jedi
decision, exact asset hashes, capability matrix, memory measurement scope, and
Android 9–16 results.

## M5 LuaLS companion process

Lua semantics use LuaLS `3.18.2`, tag object
`6dc1a32a141c69d8d52856a8b26f966f624fc76f`, commit
`b5e57c36a9a27b89eb283861fb8946fa787e37d8`, and the exact submodule revisions
recorded in `luals-build-lock.json`. The build targets Android API 28 with NDK
`29.0.14206865` and static libc++, producing verified executables for
`arm64-v8a`, `armeabi-v7a`, and `x86_64`.

Rebuild and verify a distribution in an isolated output directory with:

```powershell
.\tools\ace-lsp\build-luals-android.ps1 `
  -NdkRoot <android-sdk>\ndk\29.0.14206865 `
  -OutputRoot build\luals-android\dist
```

Pass `-InstallProjectRoot <repository-root>` only when intentionally replacing
the committed `app/src/main/assets/luals` and `app/src/main/jniLibs` copies.
Normal APK assembly never clones or compiles LuaLS; it packages the committed,
hash-locked distribution. Verify the committed runtime, ELF class/machine and
dependencies, deterministic manifest, browser wiring, protocol behavior,
unsupported-ABI fallback, and restart lifecycle with:

```powershell
.\gradlew.bat :app:verifyAutoJs6LuaLanguageServer
```

The provider supplies completion, hover, signature help, diagnostics, and
definition through the M3 JSON-RPC/LSP core and Android stdio transport. The
native command and environment are selected from an application-side allowlist;
JavaScript can reference only the opaque `lua-luals` provider ID. LuaLS receives
one canonical physical project root, and document/workspace URIs are rejected if
they escape it.

The universal APK contains real LuaLS executables only for the three supported
ABIs. A 1,256-byte dependency-free x86 ELF exists solely so Android can install
the universal APK on legacy x86 devices; it is not registered or executed.
Those devices report `bundled-luals-unavailable-for-abi` and silently retain the
M2 Lua index plus the existing Ace syntax worker. See
`M5_LUA_SEMANTIC_ACCEPTANCE.md` for exact hashes, controlled upstream patches,
size accounting, capability and failure-path evidence, and Android 9–16 results.

## TypeScript execution-profile diagnostics

The bundled language service is pinned to TypeScript `6.0.3`, the same version
used by the compiler plugin. TypeScript documents use the compiler's current
revision-2 defaults instead of the more permissive JavaScript editor defaults:

| Editor document | Profile | Target | Module | Resolution | Strict | Default lib |
| --- | --- | --- | --- | --- | --- | --- |
| standalone `.ts` / `.tsx` | `rhino` | ES2018 | CommonJS | Node10 | yes | `lib.es2018.d.ts` |
| `.ts` / `.tsx` below the nearest `project.json` with `type: node` | `node` | ES2018 | NodeNext | NodeNext | yes | `lib.es2018.d.ts` |
| `.mts` / `.cts` | `node` | ES2018 | NodeNext | NodeNext | yes | `lib.es2018.d.ts` |

Rhino diagnostics also use the execution factories `__autojs6Tsx` and
`__autojs6TsxFragment`. Declaration files follow the corresponding `.d.ts`,
`.d.mts`, or `.d.cts` profile. JavaScript documents retain the editor-oriented
ES2022 configuration because they do not pass through the TypeScript execution
compiler.

For a local Rhino or Node TypeScript project, Android freezes the project's
compilation-relevant `node_modules` text with the compiler dependency layer's
same boundary, exclusions, quotas, inventory hash, and layer hash. The bridge
publishes immutable `file:///autojs6/editor/node_modules/...` URIs and installed
`@types` directive names. The language service therefore resolves package
`types`/`typings`, TypeScript 6 `typesVersions`, nested declaration imports, and
ambient `@types` from the same exact dependency snapshot used at compilation.
Resolver policy revision 3 also resolves a runtime-only JavaScript root through an installed
DefinitelyTyped package without overriding bundled declarations; the dual-profile verifier locks
this behavior with `lodash@4.17.21` and `@types/lodash@4.17.25`. Revision 3 is fingerprinted as
`6241375f2ea49ac2c2d2b3b79b28b7c1ee4adde75c989defc61e252c89ced2bd`.

The Ace service still treats project source as a single-document hinting layer:
dependency declarations are project-aware, but controlled `tsconfig.json`
overrides and cross-source diagnostics remain authoritative only in the
pre-execution compiler until Roadmap T4. Once a dependency type layer is
present, missing-module and missing-declaration diagnostics are no longer
suppressed. If TypeScript cannot load, has the wrong bundled version, or
exceeds the editor's semantic limit, Ace falls back to static/JSHint
assistance; script execution does not depend on the editor service.

Run the all-group TypeScript completion/semantic checks and old-WebView
fallback verification, including the exact Rhino/Node profile option gate and
the dual-profile dayjs `typesVersions`, ambient `@types`, and lodash DefinitelyTyped fixtures,
with:

```powershell
.\gradlew.bat :app:verifyAutoJs6LspRuntime
```
